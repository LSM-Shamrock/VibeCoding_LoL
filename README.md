# FROSTBRIDGE · 서리 다리

Pygame + OpenGL로 만든 **플레이 가능한 3D 싱글 레인 MOBA 프로토타입**입니다.
로비 → 방 생성/입장 → 방장 시작 → 캐릭터 선택 → 전투 → 승패 → 재경기까지 연결되어 있습니다.

## 바로 실행

Windows에서는 **`start.bat`을 더블 클릭**하세요. Python 3.11 이상이 필요합니다.
가상환경과 라이브러리가 없으면 최초 실행 때 설치합니다.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

화면에서 **혼자 시작 · 봇 연습**을 누르면 1 대 1 봇 연습 방이 만들어집니다.
캐릭터를 고르고 **선택 완료**를 누르면 전투가 시작됩니다.
5 대 5 연습은 **내 PC에서 서버 열기 → 방 만들기(5명) → 빈 자리 봇 채우기 → 캐릭터 선택 시작**으로 진행하세요.

그래픽 드라이버의 OpenGL 2.1 호환 프로필이 필요합니다. 홈·로비·대기실·캐릭터 선택은 기본 1280×720 창 모드로 실행됩니다.
전투에 들어가면 전체화면으로 전환하고, 로비나 대기실로 돌아오면 이전 창 크기와 위치로 복원합니다.
모든 UI는 1280×720(16:9) 기준으로 배치하며, 화면 비율이 달라도 글자·초상화·버튼이 늘어나지 않습니다.
Esc 메뉴 등의 어두운 배경은 16:9 바깥 여백까지 화면 전체를 덮습니다.
미니맵의 지형·유닛·클릭 좌표는 전장 카메라의 대각선 투영 방향과 일치합니다.
전장은 화면 전체에 렌더링됩니다. 종료는 홈 화면의 **게임 종료** 또는 Alt+F4를 사용하세요.
화면 글꼴은 Windows 맑은 고딕을 우선 사용하며 다른 OS에서는 Noto Sans CJK KR/NanumGothic을 설치하세요.

## 친구와 플레이

1. 한 명이 **내 PC에서 서버 열기**를 누릅니다. 기본 TCP 포트는 **27355**입니다.
2. 나머지 플레이어는 서버 PC의 LAN IPv4 주소와 포트를 입력합니다. 예: `192.168.0.12:27355`.
3. **서버에 접속**하고 같은 방에 들어갑니다.
4. 방장이 1~5명씩 팀을 구성합니다. **팀 변경**, 팀별 **봇 추가/제거**, **빈 자리 봇 채우기**를 사용할 수 있습니다.
5. 양 팀의 슬롯을 채우고 방장이 시작합니다. 모든 사람이 선택을 확정하면 게임으로 전환합니다.

같은 PC에서 창 두 개로 시험할 때는 첫 번째 창만 서버를 열고, 두 번째 창은 `127.0.0.1:27355`에 접속하세요.
이미 서버가 실행 중이면 새 서버를 열지 않고 해당 서버에 접속합니다.
서버 PC에서 방화벽이 묻는 경우 사용할 네트워크의 Python 연결을 허용해야 합니다.

별도 서버 프로세스도 실행할 수 있습니다. 서버는 그래픽 라이브러리를 import하지 않습니다.

```powershell
.\.venv\Scripts\python.exe server.py --host 0.0.0.0 --port 27355
```

방 목록은 **접속한 서버 안의 목록**입니다. 인터넷 중앙 매칭/자동 LAN 검색/NAT 중계는 없습니다.
다른 네트워크에서 플레이하려면 외부에서 도달 가능한 서버 주소와 네트워크 설정이 필요합니다.
현재 서버는 신뢰하는 사용자끼리 쓰는 개발/LAN 버전이며 계정 인증·암호화·재접속 복구는 구현하지 않았습니다.
내장 서버를 연 앱을 종료하면 해당 서버의 방도 종료됩니다. 방만 나가면 서버는 계속 실행됩니다.
방장이 방에서 나가면 남은 사람에게 방장 권한을 넘기며, 게임 중 나간 플레이어는 봇으로 대체합니다.
선택 중 누군가 나가면 대기실로 돌아가 빈 자리를 채웁니다. 모든 사람이 나간 방은 삭제됩니다.

## 조작

| 입력 | 동작 |
|---|---|
| 우클릭 / 우클릭 유지 | 바닥: 이동, 적: 추적해서 기본 공격 |
| A | 마우스 지점까지 공격 이동 |
| S | 이동 및 추적 정지 (근처 적 자동 공격은 유지) |
| Q / W / E | 캐릭터별 스킬, 마우스 방향으로 즉시 사용 |
| R | 궁극기 (레벨 6부터) |
| D | 눈덩이 표식, 적중 후 3초 안에 재사용하면 대상에게 돌진 |
| F | 마우스 방향으로 점멸 |
| P / 하단 골드 영역 클릭 | 상점 열기/닫기 |
| 상점에서 1~6 | 해당 아이템 구매 |
| Tab 유지 | 전적 확인 |
| 마우스를 화면 가장자리로 이동 | 해당 화면 방향으로 자유 카메라 이동 |
| Space 유지 | 누르는 동안만 내 캐릭터 추적, 놓으면 자유 시점 |
| 방향키 / 미니맵 클릭 | 자유 카메라 이동 |
| 마우스 휠 | 확대/축소 |
| Esc | 전투 메뉴 (온라인 전투는 계속 진행) |

기본 카메라는 자유 시점입니다. 상점·전적·Esc 메뉴가 열렸거나 앱이 포커스를 잃으면 가장자리 스크롤이 멈춥니다.
인게임 상단의 로고와 메뉴 버튼은 표시하지 않으며, 메뉴는 Esc로 열고 닫습니다.
인게임 HUD는 하단 중앙의 QWER 및 그 아래 체력·마나, 우측의 D/F와 3×2 아이템 슬롯으로 구성됩니다.
미니맵은 오른쪽 아래, 팀 킬·개인 K/D/A·시간은 오른쪽 위에 표시합니다.
상시 키 설명은 숨기고, 스킬·아이템 상세 정보는 마우스를 올릴 때 표시합니다.

## 구현된 전투 규칙

- 단일 공격로에서 양 팀 1 대 1~5 대 5. 정글/귀환 없음.
- 팀마다 외곽 포탑 → 내부 포탑 → 억제기 → 넥서스 포탑 2개 → 넥서스.
- 앞 구조물이 살아 있으면 다음 구조물에 피해를 줄 수 없습니다. 넥서스가 파괴되면 즉시 승패가 확정됩니다.
- 근처에 아군 미니언이 없으면 적 포탑/넥서스에 주는 피해가 감소합니다.
- 포탑은 미니언을 우선 공격하며, 보호 범위에서 아군 영웅을 공격한 적에게 어그로를 전환합니다.
- 미니언은 8초에 첫 생성, 이후 20초 간격으로 생성됩니다. 3번째 웨이브마다 공성 유닛을 생성합니다.
- 억제기 파괴 시 상대의 슈퍼 미니언이 생성되며 억제기는 180초 뒤 재생합니다.
- 3레벨/1375골드로 시작합니다. 경험치·골드 획득, 자동 성장(최대 18), 처치/어시스트 보상, 사망/부활이 있습니다.
- 상점은 최초 출발 전, 사망 중, 부활 후 재출발 전 이용할 수 있습니다. 단순히 기지로 돌아와도 다시 열리지 않습니다.
- 기지에서 즉시 회복되지 않습니다. 기본 체력/마나 재생, 지원가 치유, 4곳의 회복 유물을 이용합니다.
- 회복 유물은 습득자에게 먼저 회복을 주고 2초 뒤 주변 양 팀에 회복을 줍니다. 45초 뒤 재생합니다.
- 서로 다른 능력치와 QWER 조합을 가진 자체 캐릭터 6종, 아이템 6종/슬롯 6개, 표식·점멸을 제공합니다.
- 봇은 진격·교전·스킬 사용·저체력 후퇴·유물 탐색·아이템 구매를 수행합니다.

**LoL의 현재 칼바람 규칙을 완전히 복제한 버전은 아닙니다.** 요청한 방/선택 흐름을 구현하고 칼바람의 핵심 전투 구조를 적용한 첫 버전입니다.
팀 크기와 직접 캐릭터 선택은 요청대로 변경했으며, 맵 크기·주기·능력치·성장·피해 공식은 이 프로젝트 자체 값입니다.
실제 LoL 챔피언/아이템 전체, 룬, 무작위 배정/교환, 수풀·시야/전장의 안개, 마법 저항력·치명타 등 전체 전투 공식,
헥스게이트, 우물 포탑, 패치별 모드 보정, 효과음, 정교한 경로 탐색·유닛 간 충돌은 아직 구현하지 않았습니다.
스킬은 레벨에 따라 자동 성장하며 별도 스킬 포인트 UI는 없습니다. 스킬의 구조물 피해도 지원하지 않습니다.
게임을 확장할 때 이 항목들을 따로 추가할 수 있도록 시뮬레이션·네트워크·렌더러를 분리했습니다.

## 초상화와 3D 모델 교체

초상화는 `assets/portraits/`, 인게임 모델은 `assets/models/`에 넣고 **`data/champions.json`**을 수정하세요.

```json
{
  "id": "mage",
  "portrait": "assets/portraits/my_mage.png",
  "model": "assets/models/my_mage.glb",
  "model_scale": 1.0,
  "model_rotation": [0, 0, 0]
}
```

위 내용은 기존 캐릭터 항목에서 수정할 필드의 예시입니다. 나머지 능력치와 `skills` 필드는 유지하세요.
모델은 **GLB / glTF / OBJ**를 지원합니다. GLB의 기본 색상 텍스처, OBJ+MTL의 색상/텍스처, 정점 색상과 씬 변환을 읽습니다.
높이를 자동 조정해 발을 바닥에 놓습니다. 위쪽은 **Y**, 정면은 **+Z**입니다.
Z-up 모델은 `model_rotation`을 `[-90, 0, 0]` 등으로 조정하세요.
상세 규격은 `assets/models/README.md`에 있습니다.

리소스가 없어도 코드로 만든 2D 초상화와 3D 임시 캐릭터로 플레이할 수 있습니다.
`model`을 `assets/models/example_crystal.obj`로 바꾸면 포함된 샘플 모델을 시험할 수 있습니다.
**현재 모델 로더는 정적 메시용입니다. 본 애니메이션·스키닝·PBR은 후속 구현이 필요합니다.**
리소스/데이터를 변경하면 서버와 클라이언트를 다시 실행하고, 함께 플레이할 PC에는 같은 `data`/`assets`를 배포하세요.
기존 6개 캐릭터의 리소스와 능력치 교체는 데이터로 처리할 수 있으며, 7번째 캐릭터부터는 선택 화면 레이아웃 확장도 필요합니다.

## 구조와 검증

```text
main.py / start.bat       데스크톱 실행
server.py                독립 서버 실행
frostbridge/app.py        화면 흐름, 입력, HUD
frostbridge/ui.py         Pygame UI, 초상화
frostbridge/render.py     OpenGL 전장, 기본 모델, 카메라
frostbridge/assets.py     GLB/glTF/OBJ 로더
frostbridge/network.py    TCP 서버/클라이언트, 방 상태 관리
frostbridge/simulation.py 서버 전투 판정, 봇, 성장, 구조물
data/                    캐릭터/아이템 정의
assets/                  교체 가능한 리소스
tests/                   규칙, 실제 TCP 클라이언트, 모델 로더 테스트
```

서버는 30Hz 고정 틱으로 판정하고 10Hz로 상태를 보냅니다. 클라이언트는 좌표를 보간해 렌더링합니다.
클라이언트는 이동/공격/시전/구매 의도만 보내며 체력·골드·피해·승패는 서버가 계산합니다.
입력 크기와 전송량 제한, 좌표/방장/팀 정원/구매 검증이 있습니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py --smoke-test
.\.venv\Scripts\python.exe -m tests.render_check
```

첫 명령은 GUI 없이 규칙/네트워크/모델 로더를 테스트합니다.
두 번째는 숨겨진 OpenGL 창과 로컬 서버를 사용해 홈 → 로비 → 대기실 → 선택 → 전투를 검증하고 `artifacts/`에 화면을 저장합니다.
세 번째는 GLB 텍스처·OBJ 모델을 실제 렌더링하고 전투·상점·전적·승리 화면과 바닥 좌표 변환을 검증합니다.

구현 참고: [Pygame OpenGL 창 문서](https://pyga.me/docs/ref/display.html),
[trimesh 모델 형식 문서](https://trimesh.org/formats.html).
칼바람의 모티브 참고: [Riot의 ARAM 변경 소개](https://www.leagueoflegends.com/en-us/news/game-updates/aram-2023-preview/).
이 프로젝트의 규칙값은 위 글의 특정 패치를 그대로 재현한 값이 아닙니다.
